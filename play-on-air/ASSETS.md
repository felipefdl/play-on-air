# Store assets (icon and logo)

Home Assistant Apps presentation expects two PNG files **next to** `config.yaml` in this folder. They are not generated by CI — drop the final art here before publishing the store listing.

| File | Role | Spec |
|------|------|------|
| `icon.png` | Store / app icon | PNG, **1:1 square**, recommended **128×128** px |
| `logo.png` | Store / detail header | PNG, recommended ~**250×100** px (landscape is fine) |

## Tips

- **Transparent background** preferred so the mark works on light and dark UI.
- **Icon:** high-contrast mark that stays readable at small size (sidebar / list tiles). Prefer a simple symbol over fine text.
- **Logo:** wordmark or mark + wordmark; keep padding so it does not clip in the store card.
- Do not commit placeholder or AI-draft art as the official brand unless the maintainer approves it.
- Filenames are fixed: `icon.png` and `logo.png` (lowercase).

Until both files exist, the store may show a generic puzzle icon. That does not block install or runtime.

## Sources

| File | Role |
|------|------|
| `logo.svg` | The logo: black art on white |
| `mark.svg` | The logo on a rounded espresso tile (`#3d2618` → `#1e120b`, border `#5a3a24`): amber-to-orange art (`#ffc46b` → `#f0703a`), cream play button (`#fff1dc`); the README banner links to it |
| `wordmark.svg` | `mark.svg` followed by "PlayOnAir" in Geist Bold, converted to outlines (cap height half the tile, amber-to-orange `#ffb24f` → `#ec6430`), readable on light and dark themes |

`icon.png` renders from `mark.svg`, and `logo.png` from `wordmark.svg` (the app page shows it like the Music Assistant and ESPHome logos: mark plus name, no padding):

```bash
resvg -w 512 mark.svg icon.png
resvg -h 256 wordmark.svg logo.png
```
